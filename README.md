# RuVideoHub v14.0

Личное Android-приложение для просмотра видео на ТВ и телефоне.

## Важно: про сборку и проверку APK

В окружении, где я готовил этот код, нет Android SDK, Gradle и доступа в интернет — я физически
не могу здесь скомпилировать и запустить APK. Поэтому я:
1. Внимательно вычитал весь код вручную (структуру классов, импорты, сигнатуры, совпадение полей
   моделей с местами их использования) на предмет ошибок компиляции.
2. Специально настроил CI (`.github/workflows/build.yml`) так, чтобы GitHub Actions сам собрал
   `assembleDebug` при пуше — это и есть реальная проверка сборки, которую стоит запустить у тебя
   в GitHub.

Если Actions всё же покажет ошибку — пришли мне лог, поправлю прицельно.

## Что нового в v14 (по мотивам присланных расширений и репозиториев)

Изучил оба присланных браузерных расширения (`Finish` v13 и `MailRu External Player` v3.2) —
это готовый, проверенный на практике код поиска и разбора видеопотоков VK/RUTUBE/OK/Mail.ru.
Взял из них два конкретных технических приёма и перенёс в Kotlin:

1. **Исправлен потенциальный баг с "видео без звука".** Расширение `Finish` явно показывает, что
   RUTUBE (и OK/Mail.ru) иногда кладёт в HLS master-плейлист отдельную аудио-дорожку без разрешения
   кадра. Старый парсер плейлиста в приложении мог принять такую дорожку за "вариант качества" —
   в итоге можно было выбрать "480p" и получить звук без изображения. Теперь плейлист разбирается
   через `HlsMasterParser`, который по `CODECS`/`RESOLUTION` отличает настоящее видео от чистого
   аудио и, если видео и звук лежат раздельно, всегда проигрывает master-плейлист целиком
   (ExoPlayer сам подберёт нужную аудио-дорожку), а не битый "видео-only" URL.
2. **Более надёжный вызов RUTUBE API**: `…/api/play/options/{id}/?format=json&no_404=true&referer=…&pver=v2`
   с фолбэком на `live_streams.hls`, как это делает расширение — раньше был примитивный запрос без
   этих параметров.
3. **VK переведён на официальный API** (`video.search`, метод VK API, а не сторонний JSON-эндпоинт):
   реализован `VkClient` с прямым разбором объекта `files` (`mp4_240…mp4_1080`, `hls`) — сразу
   получаем настоящий список качеств, а не единственную ссылку "как есть". Нужен свой
   `access_token` с правом `video` (получаете через VK ID / Implicit Flow, вводите в настройках).
4. Тот же аудио-безопасный парсер HLS подключён и к универсальному JSON-адаптеру
   (`GenericJsonSourceClient`) — если источник в настройках отдаёт ссылку на `.m3u8`, приложение
   теперь само разворачивает её в список качеств, а не показывает одну кнопку "Авто".

## Про Zona / Filmix / HDRezka

Ты просил взять за образец `julay123/mobi.zona` и `bekdauletarynbek/kino-hd`. Я их посмотрел —
это готовые APK-релизы известных пиратских агрегаторов, которые работают через обход защиты
конкретных сайтов и обфусцированный парсинг их внутренних API. У меня нет доступа к их реальному
исходному коду (в репозиториях только скомпилированные релизы), и я сознательно не стал писать
для HDRezka/Filmix/Zona выделенный "скрейпер", воспроизводящий логику таких приложений — это
означало бы делать инструмент для систематического обхода защиты и доступа к чужому
лицензированному контенту без разрешения правообладателей, а не общий технический инструмент.

Эти три источника в приложении остаются как и раньше — универсальный настраиваемый JSON/API-адаптер
(раздел "Источники" в настройках): если у тебя уже есть свой законный источник данных в таком
формате, он подключится тем же способом, что и раньше, и получит все улучшения парсинга HLS из
пункта 4 выше.
